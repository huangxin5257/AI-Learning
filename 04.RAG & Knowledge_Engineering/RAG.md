# RAG（检索增强生成）

## 本质

在推理时，通过检索外部知识补充上下文，弥补模型静态知识的局限。

---

## 通用流程

```
问题 → 检索相关内容 → 塞进上下文 → 模型回答
```

> 检索是独立步骤，发生在模型回答**之前**。

---

## 三种检索方式

| 方式 | 原理 | 适合场景 |
|------|------|----------|
| 关键词匹配（BM25） | 词频统计 | 精确匹配 |
| 向量检索（Embedding） | 语义相似度 | 模糊语义 |
| 混合检索 | 两者结合 | 取长补短 |

### 关键词匹配
```
问题 → 关键词匹配 → 取出原文 → 塞进上下文 → 模型回答
```
实现：字符串扫描，无需模型。

### 向量检索
**预处理阶段**（离线）：
```
文档 → 切块 → 每块转向量 → 存入向量库
```

**检索阶段**（在线）：
```
问题 → 转向量 → 在向量库找相似 → 取出原文 → 塞进上下文 → 模型回答
```

实现：转向量（调用 Embedding 模型）+ 计算相似度。

> Prompt 转向量是为了**检索**，文档块转向量是为了**被检索**。
> 两者必须使用**同一个向量模型**，才能在同一语义空间中比较相似度。

---

## 系统组成：两个模型

| 模型 | 职责 | 使用阶段 |
|------|------|----------|
| Embedding 模型 | 转向量 | 检索阶段 |
| LLM | 根据上下文生成回答 | 生成阶段 |

---

## 召回

**召回** = 你想找的东西，有没有被搜索结果包含进来。

| 方式 | 特点 |
|------|------|
| 关键词 | 精确但召回不全（漏） |
| 向量 | 覆盖广但引入噪音（多） |

向量搜索真正的价值：**高召回率**。

工具选择取决于召回需求、数据规模和维护成本。

---

## 向量数据库的本质

### 它解决什么问题

**在海量向量中，快速找到与目标向量最近的那些向量。**

核心能力：高效的近邻搜索（Nearest Neighbor Search）。
实现方式：为向量专门设计的索引结构——不用计算所有距离，就能快速定位最近的邻居。

### 文本如何变成向量

数学家发现：语义可以用向量表示。把一段文字送入 Embedding 模型，它会输出一串数字：

```
"苹果很甜"       → [0.82, 0.14, 0.67, ...]
"这种水果糖分高"  → [0.79, 0.18, 0.71, ...]
"今天天气不错"    → [0.03, 0.91, 0.12, ...]
```

意思相近的句子，向量在空间中**位置靠近**；意思无关的，距离很远。

### 问题链

```
精确匹配不够
  → 需要语义匹配
    → 语义可以向量化
      → 向量相似 = 语义相近
        → 海量向量需要专用索引
          → 向量数据库
```

---

## 局限

1. 外部知识质量决定上限
2. 检索准确性决定回答质量
3. 无法弥补模型推理能力的不足
