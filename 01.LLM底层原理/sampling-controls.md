# Sampling Controls

LLM 每次生成 token 时，不是直接选一个答案，而是给词表里所有词打概率分。**Sampling Controls** 就是控制"怎么从这堆概率里挑出最终那个词"的参数。

---

## 示例背景

用"今天天气很\_\_\_"来举例，假设模型给出以下概率：

| 词 | 概率 |
|----|------|
| 好 | 50% |
| 热 | 30% |
| 差 | 15% |
| 冷 | 5% |

---

## Temperature（温度）

> 控制模型"敢不敢冒险"

- **Temperature 低**（如 0.1）：几乎每次都选"好"，回答稳定但单调
- **Temperature 高**（如 1.5）：可能选"差"或"冷"，回答更有变化、更有创意

**适用场景：** 需要准确答案时调低，需要创意内容时调高

---

## Top-K

> 只看排名前 K 的选项

- **Top-K = 2**：只考虑"好"和"热"，直接忽略其他词
- 就像餐厅只给你看销量前两名的菜，其他菜不存在

**适用场景：** 想限制模型的"发挥范围"，避免出现离谱的词

---

## Top-P

> 累计概率凑够 P% 就停，动态个数

- **Top-P = 0.8**：把"好(50%) + 热(30%)"加起来 = 80%，只从这两个里选
- 如果某个词独占 90% 概率，那就只有它一个候选词
- 比 Top-K 更灵活：概率集中时候选少，分散时候选多

**适用场景：** 比 Top-K 更常用，自动适应概率分布的形状

---

## 三者关系

通常同时使用，执行顺序：**Top-K → Top-P → Temperature**

先缩小候选范围，再用 Temperature 决定最终如何采样。

### 完整流程示例

仍以"今天天气很___"为例，参数设置：Top-K = 3，Top-P = 0.8，Temperature = 0.7

**原始概率：**

| 词 | 概率 |
|----|------|
| 好 | 50% |
| 热 | 30% |
| 差 | 15% |
| 冷 | 5% |

**第一步 Top-K = 3**：只保留前 3 名 → `好(50%)、热(30%)、差(15%)`，`冷` 被淘汰。

**第二步 Top-P = 0.8**：累计到 80% 为止 → `好(50%) + 热(30%) = 80%`，刚好够，`差` 被淘汰。候选池缩为 `好、热`。

**第三步 Temperature = 0.7**：对 `好(50%)、热(30%)` 重新归一化后（好≈62%、热≈38%），按此概率随机抽取最终词。

> 结果不是固定的——大概率输出"好"，也有一定概率输出"热"。
